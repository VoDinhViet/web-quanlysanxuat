## Layer boundaries (non-negotiable)

- A route file (`src/routes/**`) contains only `createFileRoute`, `validateSearch`, `beforeLoad`,
  `loader`, `pendingComponent`, and a `component` pointing at a page in `src/features/`. Its
  `pendingComponent` is the shared `LayoutPagePending`
  (`src/components/shared/layouts/LayoutPagePending.tsx`), never a route-specific loader.
  Exception: a layout route (e.g. `src/routes/(authed)/route.tsx`) may hold provider/shell JSX.
- A list route may split into a layout route (a directory's `route.tsx`: real `PageTitleBar` +
  `<Outlet/>`, no loader, so the header never blocks) plus a data-owning child (usually
  `index.tsx` with the normal `validateSearch`/`loader`/`component`). The child's
  `pendingComponent` is then `PagePending` (`src/components/shared/layouts/PagePending.tsx`,
  content-only) — `LayoutPagePending` would stack a second header under the real one. See
  `src/routes/(authed)/manage_/production-jobs/`. Opt-in; most routes stay flat.
- Business logic lives in `src/features/<domain>/`. A feature reads another feature only through
  that feature's `api/index.ts` barrel (e.g. `import { unitOptionsQueryOptions } from
"@/features/units/api"`) — never its `components/`, `pages/`, `hooks/`, `schemas/`,
  `api/options/` or `api/server-functions/`. The barrel exports queryOptions factories and
  option hooks only, never a raw server function, so a caller can't bypass the query cache.
  Enforced by ESLint (the `qlsx/*` import-boundary rules in `eslint.config.js`). Code with no
  single owning feature promotes to `src/lib/` or `src/components/shared/`.
- `src/routeTree.gen.ts` is generated by the TanStack Start plugin. Never hand-edit it.
- A trailing underscore on a route folder (`manage_/orders.tsx`) keeps the URL segment nested
  under the parent path without inheriting the parent's layout.
